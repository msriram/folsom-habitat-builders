# Developer Guide

This document contains the technical instructions for running and maintaining the Folsom FLL Team Hub.

## Requirements

- Git
- A modern web browser
- Python 3 or another static HTTP server for local preview
- Node.js for repository validation scripts
- Access to the configured Supabase project for database or authentication work

## Local preview

Run the static site from the repository root:

```bash
python3 -m http.server 8000
```

Open [http://localhost:8000](http://localhost:8000) in a browser.

Do not open the HTML files directly from the filesystem. Authentication modules, imports, and browser security controls expect an HTTP origin.

## Validation

Check internal page, script, stylesheet, and asset references:

```bash
npm run check
```

For JavaScript files that do not use browser-only module syntax, syntax can also be checked with:

```bash
node --check assets/js/main.js
```

## Repository layout

- Root HTML files are GitHub Pages routes.
- `assets/css/styles.css` contains shared visual styles.
- `assets/js/main.js` builds the shared header, navigation, account menu, and footer.
- Page-specific behavior is under `assets/js/`.
- `supabase/migrations/` contains ordered production database changes.
- `supabase/functions/` contains Edge Functions and must never contain embedded secrets.
- `docs/` contains operational documentation.

## Configuration and secrets

`assets/js/portal-config.js` contains only the Supabase project URL and publishable browser key. Publishable keys are expected to be visible in the browser and must be protected by Row Level Security.

Never commit any of the following:

- OpenAI secret keys
- Supabase service-role or secret keys
- Database passwords or connection strings containing passwords
- Google OAuth client secrets
- Shared website or third-party passwords
- Private student records or unredacted receipts

Production secrets belong in Supabase Edge Function Secrets.

## Database changes

Create a new numbered SQL file under `supabase/migrations/`. Database tables exposed to the browser must have Row Level Security enabled and explicit policies for every required operation.

Before applying a migration:

1. Review existing tables and policies.
2. Make the migration safe to run once in production.
3. Verify student, parent, and coach boundaries separately.
4. Run Supabase security and performance advisors after the change.

See [Team Room Deployment](PORTAL_SETUP.md) for the current access model.

## Publishing

The repository deploys to GitHub Pages from `main`. For a routine update:

```bash
git status
git add <changed-files>
git commit -m "Describe the website change"
git push origin main
```

Deployment progress is available in [GitHub Actions](https://github.com/msriram/folsom-fireflies/actions).

The published website is [https://msriram.github.io/folsom-fireflies/](https://msriram.github.io/folsom-fireflies/).

## Updating shared navigation or styles

Shared navigation is generated by `assets/js/main.js`. After modifying shared JavaScript or CSS, update the corresponding query-string version in HTML references so GitHub Pages visitors do not receive a stale cached asset.

## Child privacy

Do not add children’s full contact information, home addresses, school schedules, private account information, or unapproved identifiable media to Git. Use authenticated Supabase records and private Storage buckets for team-only information.
